# 工具适配

按当前环境提供的能力执行核心流程，不要求特定产品、MCP 服务或其他 skill。`SKILL.md` 和报告模板共同构成完整流程；`agents/openai.yaml` 仅提供 Codex 的展示信息。

## 按能力选择工具

| 任务 | 可用方式 | 需要取得的结果 |
| --- | --- | --- |
| 读取项目背景 | 文件读取工具、文件搜索、终端中的 `rg` | 项目约定、依赖清单、相关模块、旧报告 |
| 发现候选 | 联网搜索、GitHub 搜索、已连接的仓库工具、包管理器与官方文档 | 候选地址与对应需求 |
| 核查仓库 | 仓库工具、网页读取、`gh`、浅克隆或指定版本下载 | README、许可证、相关源码、发布和问题处理证据 |
| 最小验证 | 终端、项目局部依赖环境、当前可用的隔离运行环境 | 版本、环境、命令、实际结果 |
| 保存报告 | 文件写入工具 | Markdown 报告及需要保留的验证材料 |

GitHub CLI 或连接器可用时直接使用；公开仓库也可通过网页或 Git 读取。每种方式都应保留仓库版本与来源，无法访问的内容保持未核查状态。

## 不同宿主的使用方式

- **Codex**：使用当前会话实际提供的文件、联网和终端能力。支持隐式调用时，按技能描述匹配新项目请求；显式调用可使用 `$open-source-scout`。
- **Claude Code 及其他支持 `SKILL.md` 的工具**：让宿主发现完整技能目录，按其原生技能机制调用；只依赖标准的 `name`、`description` 和 Markdown 指令，具体命令与权限沿用宿主约定。
- **工具能力不足的环境**：能联网就完成来源核查，能执行就完成最小验证。无法访问或运行的部分明确列为未核查或未验证；影响硬性要求的关键缺口需解决后再定案。无法联网时，可整理需求和用户提供的候选，但将当前选型状态保持为待定。

自动触发依赖宿主是否加载并选择该技能；核心流程无需绑定工具名称或修改宿主配置。迁移时保留整个技能目录，确保相对路径引用仍然有效。
